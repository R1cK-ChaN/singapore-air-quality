# 这个项目怎么和 Agent 一起做出来的

[返回首页](../README.md)

最开始，我想每天看一下新加坡各区的空气质量，顺便把结果画成图发出来。下面记录几个实际做过的修改，方便你复现，也方便把同样的方法用在自己的项目上。

## 先取数，再画图

我先让 Agent 找到官方数据源，写脚本下载，保存原始 JSON 和 CSV。确定有数据以后，再讨论地图和折线图。

保存输入后，改字体和排版时可以反复使用同一份数据。看到一个数字不对，也能回头核对。

## 看着成品改需求

| 看到的问题 | 当时怎么改 |
| --- | --- |
| 区域折线右边空了一大截 | 改为昨日11点至今日11点，共25个小时读数 |
| 地图两侧留白太多，区域只有名字 | 放大地图，每个标识上方区域、下方数值 |
| 57.7的点仍然是绿色 | 根据每个点的数值换色，连线跨过阈值也换色 |
| 图片里标题、说明太多 | 删除重复信息，保留数据、必要标签和来源 |
| 想沿用每天相同的样式 | 将字体、白底和渐变写进绘图代码 |

这些修改不需要一开始全部想好。先看一份真实输出，哪里不顺手，就具体指出来。

## 把重复步骤交给代码

取数、计算和绘图每天都要做，来源与规则已经固定，就适合写成脚本。下次直接运行，省去模型再次查询、整理和生成的调用，也减少了编错数字或混淆日期的机会。

代码也可能写错，所以仍要核对结果。这里的测试覆盖日期、官方数据修订、缺失值、分档边界和时间窗口等问题。

## 到第二天才容易发现的细节

11点的数据可能11点之后才发布。因此，每日脚本等待五区11点读数齐全，不用更早时刻的数据顶替。

昨天上午保存的文件只有半天数据。今天要画过去24小时，就得把昨天下午和晚上的部分补回来。脚本会刷新不完整的历史缓存。

每天都在同一个时点截止，即使补跑时已经到了下午，也只采用11点及以前的读数。

## 可以复制给 Agent 的起始需求

> 我每次需要完成这件事：［具体工作］。输入来自［接口或文件］，希望输出［图片或表格］。先用一份真实数据跑完整个流程，保存原始输入让我核对。等我确认结果后，把重复步骤写成脚本，说明下次怎么运行。缺数据就报告，不要自行补值。

如果直接从这个仓库修改，可以把这个需求和 README 一起交给 Agent：

> 帮我运行这个项目，生成指定日期的两张空气图。先按 README 安装环境与字体，确认日期和11:00读数，再出图。之后我会根据图片调整排版；保留数据来源、缺测处理和逐点换色规则。

## 当前的运行方式

独立运行 `daily.py` 不需要模型。作者现在使用本地 Codex 定时任务启动脚本和发送通知，这一层仍有模型调用。也可以自行用系统定时器运行脚本。仓库没有内置云端定时任务，下载代码不会自动开始每天执行。
